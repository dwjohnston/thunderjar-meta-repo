# Changing the meta-repo environment

The environment is generated by the meta-repo, a repository on the host.
`/workspace/.workspace/` is a read-only copy of its `Dockerfile`,
`devcontainer.json` and `compose.yaml`.

## Can I edit it from here?

Only in **admin mode** (the user ran `./apply.sh --admin` on the host). Then
the meta-repo is mounted at `/workspace/<its directory name>`. Find it with:

```bash
ls -d /workspace/*/apply.sh 2>/dev/null
```

If nothing is found, you are not in admin mode: describe the change to the
user (which file, what to add) instead of making it.

## Where things go

| Change | File |
|---|---|
| Add/remove a repo for everyone | `meta-repo.yaml` → `folders` |
| Keep a dir like `node_modules` off the host | `meta-repo.yaml` → `folders[].separate_mounts` |
| Keep a cache across rebuilds | `meta-repo.yaml` → `persistent_volumes` |
| New env var for everyone | `meta-repo.yaml` → `env` (key only) **and** `meta-repo.local.yaml.template` (example value) |
| A person's own values (host root, secrets, proxies, extra repos) | `meta-repo.local.yaml` (gitignored, per person) |
| New tool in the image | `.devcontainer/Dockerfile` |
| VS Code extensions, dev container features | `.devcontainer/devcontainer.json` |
| Corporate CA certs | `.devcontainer/certs/*.crt` and uncomment the block in the Dockerfile |
| Instructions for agents in the container | `.root/AGENTS.md` |
| Shared skills | `.agents/skills/<name>/SKILL.md` |

Never edit `.devcontainer/compose.local.yaml`: `apply.sh` generates it.

## Applying a change

Skills and `.root/AGENTS.md` are live-mounted, so edits show up immediately.
Everything else needs the host:

1. On the **host**: `./apply.sh` (or `./apply.sh --admin`). It needs `yq` and
   host paths, so it can't run inside the container.
2. In VS Code: **Dev Containers: Rebuild Container**.

Tell the user both steps. Agent conversations, `persistent_volumes` and
`separate_mounts` survive the rebuild. Anything else installed by hand doesn't.
